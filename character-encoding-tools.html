Character Encoding.

Three encoding families, six directions. Turn text into \uXXXX Unicode escapes, HTML entities (named, numeric or hex) or ASCII codes — and turn each one back, losslessly. Surrogate pairs rejoin into emoji, the full HTML5 entity set decodes, and anything out of range is counted rather than corrupted. Live on every keystroke, entirely in your tab — nothing is uploaded, nothing is stored.

Unicode Encode

runs in the bench above

Writes every character as a \uXXXX escape — the syntax JavaScript, JSON and many source files use to carry non-ASCII safely through ASCII-only channels. Characters above U+FFFF become surrogate pairs (👋 → \ud83d\udc4b), exactly as UTF-16 stores them. By default only non-ASCII is escaped, keeping the output readable; flip ∀ escape ASCII too to encode every single character.

Example

سلام Hello 世界 👋

↓

\u0633\u0644\u0627\u0645 Hello \u4e16\u754c \ud83d\udc4b Persian, CJK and an emoji — ASCII stays readable.

Unicode Decode

runs in the bench above

The trip home. Reads both the classic \uXXXX form and the modern \u{…} brace form, and rejoins adjacent surrogate pairs back into single emoji and astral characters. Anything malformed is left exactly as written and counted in the Left as-is stat, so a partially-corrupted dump still decodes as far as it can.

Example

\u0633\u0644\u0627\u0645 \u4e16\u754c \ud83d\udc4b \u{1F52D}

HTML Entity Encode

runs in the bench above

Makes text safe to drop into HTML. The five dangerous characters — & < > " ' — are always escaped, because they're the ones that break markup or open XSS holes. Non-ASCII is then rendered in the style you pick from the deck: named (&eacute;) for readability, numeric (&#233;) or hex (&#xe9;) for full coverage — anything without a common name falls back to numeric even in named mode.

Example · named style

<p>Save & sync — "now" © café</p>

↓

&lt;p&gt;Save &amp; sync &mdash; &quot;now&quot; &copy; caf&eacute;&lt;/p&gt; markup neutralized, accents kept readable.

ASCII Encode

runs in the bench above

Maps each character to its decimal ASCII code, space-separated — the lowest-common-denominator view of your text. Anything beyond code 127 has no ASCII representation, so it's marked with ? and tallied in the Out of range stat rather than silently mangled. Newlines, tabs and every control character get their real codes.

Questions

Asked often, answered plainly.

( 02 )
What's the difference between Unicode escapes and HTML entities?

They solve the same problem in different contexts. \uXXXX is the escape syntax of JavaScript, JSON and many source files — the language runtime interprets it. &…; is the escape syntax of HTML and XML — the markup parser interprets it. A \u00e9 inside an HTML page is just literal text on screen; you'd need &eacute; (or &#233;) there instead. Pick the family that matches where the text will be parsed.

Why does my emoji become two \uXXXX groups?

Because JavaScript strings are UTF-16, and characters above U+FFFF — emoji, many CJK ideographs, historic scripts — don't fit in a single 16-bit unit. They're stored as a surrogate pair, so the encoder writes both halves: 👋 becomes \ud83d\udc4b. The decoder rejoins them automatically, and the \u{1F44B} brace form expresses the same character as one code point if you prefer that style.

Named, numeric or hex entities — which should I use?

All three decode to the same character, so it's a readability-versus-coverage trade-off. Named entities (&eacute;) are the most readable but only exist for a subset of characters. Numeric (&#233;) and hex (&#xe9;) cover every Unicode code point with no ambiguity. The encoder lets you pick; anything without a common name falls back to numeric even in named mode, so you never lose a character.

Why do some characters become ? in the ASCII output?

Because ASCII only defines codes 0–127 — English letters, digits, punctuation and control characters. Anything beyond that — é, س, ★, emoji — has no ASCII code, so the encoder marks it with ? and counts it in the Out of range stat rather than pretending. Use the Unicode tools if those characters need to survive the trip.

Is my data saved anywhere?

No. IrisTool has no backend and no database. Encoding happens inside your browser tab and the text disappears the moment you close or refresh the page. There is nothing to leak, because nothing is ever collected.
