JavaScript Beautifier

runs in the bench above

Feeds your script through a real tokenizer — template literals with nested ${} interpolation, regex literals, strings and comments are all tracked, none of them can confuse the indenter — then reflows it with taste: one statement per line, blocks indented one level deep, } else { and }); kept tight, for(;;) headers left on a single line, and your own blank lines preserved between functions. The safety guarantee is structural: the beautifier never joins two lines, it only adds breaks after semicolons, after opening braces and before closing braces — so automatic semicolon insertion behaves exactly as you wrote it. Choose 2-space, 4-space or tab indentation from the deck, and hit ↯ Mangled sample to watch a one-line disaster become readable code.

Example

const go=async()=>{let r=await fetch("/api");if(!r.ok){throw new Error("no")};return r.json()};

↓

const go = async () => { let r = await fetch("/api"); if (!r.ok) { throw new Error("no"); } return r.json(); };

JavaScript Minifier

runs in the bench above

Runs the same token stream through the compactor: comments stripped, whitespace gone, and a space kept only where removing it would re-lex the code — between two words, before a regex that follows a keyword (return /re/), and between sign collisions (a + ++b stays a + ++b, never a+++b). An ASI guard preserves your line break wherever joining two tokens could change what the parser sees. The stat strip reports bytes in, bytes out, bytes saved and the reduction percentage — real bytes, not character estimates. Flip ⚡ aggressive and it also drops semicolons that sit directly before a closing brace and collapses stray empty statements.

Example

// glow function pulse(el) { el.style.opacity = 0.5; return el.hidden ? 0 : 1; }

↓

function pulse(el){el.style.opacity=0.5;return el.hidden?0:1} comment gone · whitespace gone · spaces kept only where the lexer needs them.

Questions

Asked often, answered plainly.

( 02 )
Is this a full JavaScript parser?

It's a tokenizer plus a structural reflow — one level below a full AST. It handles modern syntax confidently: template literals with nested ${} interpolation, arrow functions, async/await, optional chaining, regex literals, classes, spread and destructuring. JSX and TypeScript-only syntax are out of scope — for those, run the plain JavaScript parts through the bench first.

Can the beautifier change my program's meaning?

No, and it's guaranteed by construction: the beautifier never joins two lines, so automatic semicolon insertion can never fire differently than in your source. It only adds safe line breaks — after semicolons, after opening braces, before closing braces — and re-indents. Every token, string, template literal, comment and regex passes through byte-for-byte.

How does the minifier tell a regex from division?

With the same previous-token heuristic production minifiers use: after a value — an identifier, number, string, ), ] or } — a slash is division; anywhere else it opens a regex literal, so return /re/ keeps its space while (a) / b doesn't need one. On top of that, an ASI guard keeps an author's line break whenever joining two tokens would re-lex them into something else, like a call or a postfix increment.

What does aggressive mode do?

It drops semicolons that sit directly before a closing brace and collapses empty statements — stray ;; runs — both perfectly legal under JavaScript's semicolon rules, and both guarded so a for(;;) header is never touched. It never rewrites values, identifiers or booleans; the savings are structural, not semantic.

Is my code saved anywhere?

No. IrisTool has no backend and no database. Tokenizing happens inside your browser tab and the script disappears the moment you close or refresh the page. There is nothing to leak, because nothing is ever collected.
