CSV Viewer

          runs in the bench above
        

        

          
Turns a wall of comma-separated text into a real table the moment it lands. The header row pins to the top, zebra striping keeps rows readable, and clicking any column header sorts — numerically when the column is numbers, alphabetically otherwise. Then Copy as table puts two formats on your clipboard at once: a tab-separated version for Excel and Google Sheets (it lands as real cells) and a styled HTML table for Word, Docs and email. This is a real parser: quoted fields keep their embedded commas, so "Armstrong, Neil" stays in one cell.

          

            Example · view, sort, copy as table
            
name,missions
"Armstrong, Neil",3
Buzz Aldrin,2

            ↓
            
a live 2-column table → click "missions" to sort → Copy as table → paste into Excel and it arrives as cells, not text.

TSV Viewer

          runs in the bench above
        

        

          
The same live table, reading tabs instead of commas. Because tabs almost never appear inside real data, TSV sidesteps most of CSV's quoting headaches, which is why it's the default for bioinformatics files, database exports and log dumps. Same pinned header, same click-to-sort columns, same Copy as table — paste into Excel or Google Sheets and it arrives as a proper grid, ready to work with.

          

            Example · tabs, no quoting needed
            
gene	count	expressed
BRCA1	1240	true
TP53	980	true

            ↓
            
a clean 3-column table — click "count" to sort numerically, then copy it straight into a sheet.

          03 / 04
          
CSV Formatter

          runs in the bench above
        

        

          
Takes messy, machine-spit CSV and makes it consistent and import-safe. It parses properly, squares up ragged rows to a uniform column count, and re-emits with normalized quoting — minimal by default (only fields that need quotes get them), or quote-every-field for importers that like it explicit. Toggle trim to strip stray whitespace from every field, and sort rows to order the body by the first column. Embedded quotes are doubled correctly on the way out.

          

            Example · trim + normalize
            
name, role ,missions
"Armstrong, Neil", Commander , 3
Buzz Aldrin,LM Pilot,2

            ↓
            
name,role,missions
"Armstrong, Neil",Commander,3
Buzz Aldrin,LM Pilot,2   ← trimmed, quoted only where needed

          

          
Use it for cleaning exportsnormalizing before importdiffinghandoffs

          runs in the bench above

Useful when a tab-delimited export arrives with ragged columns or stray spaces that break a downstream import — run it through once and every row has the same shape, ready for the next step of the pipeline.

          

            Example · squaring up ragged rows

1	Ada	99
2	Grace	97	extra

            ↓

1	Ada	99
2	Grace	97   ← every row now has the same shape

Questions
Asked often, answered plainly.

        ( 02 )
      


      

        How does Copy as table work?
        
It puts two formats on your clipboard at once: a tab-separated plain-text version and a styled HTML table. Paste into Excel or Google Sheets and the tab-separated version lands as real cells you can immediately work with; paste into Word, Google Docs or an email and the styled HTML table comes through with its header row. One click, and whichever format the destination understands is the one it gets.

      

      

        What's the difference between CSV and TSV?
        
The delimiter. CSV separates fields with commas, TSV with tabs. Because commas appear constantly inside real data — names, numbers, sentences — CSV needs quoting rules to keep fields intact; TSV sidesteps most of that since tabs rarely appear inside fields, which is why it's popular for data exports, bioinformatics and logs. The viewers and formatters here handle both identically, just with a different separator.

      

      

        How are quoted fields handled?
        
With a real parser, not a naive split on the delimiter. Quoted fields can contain commas, tabs and even newlines; doubled quotes ("") become a literal quote; and the closing quote is tracked correctly. On output, the formatter re-quotes any field that contains the delimiter, a quote or a newline, so nothing leaks out of its column.

      

      

        Does sorting change my data?
        
In the viewer, sorting is display-only — it reorders the rendered table without touching your input, and Copy as table copies whatever order you're currently looking at. In the formatter, the Sort rows option genuinely reorders rows (by the first column) as part of the output. Numeric columns sort numerically, everything else alphabetically.

      

      

        Is my data saved anywhere?
        
No. Stack has no backend and no database. Every parse and render happens inside your browser tab and vanishes the moment you close or refresh the page. Even the clipboard write is local. Nothing is logged, because nothing is ever collected.
