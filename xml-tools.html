XML Formatter

runs in the bench above

Parses the document with the browser's native XML engine and re-emits it with consistent indentation — 2-space, 4-space or tab, your pick from the deck. The rewriter is structure-aware: tags that hold only text stay on one line, empty tags self-close, and comments, CDATA sections and processing instructions keep their places. Attribute order is preserved exactly as written. If the input doesn't parse, the output pane prints the error with its line and column instead of guessing.

Example

<book><title>Dune</title><author>Frank Herbert</author><year>1965</year></book>

↓

XML Beautifier

runs in the bench above

The formatter's opinionated sibling. On top of the indentation choice, it can sort every tag's attributes alphabetically — recursively, on every element in the tree — so repeated runs produce byte-identical output. That turns noisy diffs into signal: when the file changes, you know the markup changed, not the attribute order. Flip the toggle in the deck and watch every tag snap into A→Z order live.

Example

<item qty="2" sku="A-1" lang="en"/>

↓

<item lang="en" qty="2" sku="A-1"/> — attributes sorted A→Z on every tag, all the way down.

XML Minifier

runs in the bench above

Collapses the whole document to a single line by removing whitespace-only text between tags — the indentation and newlines that exist for human eyes, not for parsers. The stat strip reports bytes in, bytes out, bytes saved and the reduction percentage. Real content is never touched: meaningful text, CDATA sections, comments and attribute values survive byte-for-byte, and re-parsing the minified output yields the same tree as the original.

Example

<book> <title>Dune</title> <year>1965</year> </book>

↓

<book><title>Dune</title><year>1965</year></book> — 58 → 44 bytes · 24% smaller.

XML Validator

runs in the bench above

Answers one question — is it well-formed? — and then over-delivers either way. On success you get a full census of the document: root tag, element and attribute counts, text nodes, comments, CDATA sections, processing instructions and maximum depth, plus parse time in milliseconds. On failure you get the engine's error message, a caret dropped under the exact line and column, and fix hints for the usual suspects: mismatched closing tags, unquoted attributes, bare ampersands, duplicate attributes, unclosed tags and multiple roots.

Example

<order><total>41.75</order>

↓

✕ NOT WELL-FORMED — opening and ending tag mismatch: total / order hint: a closing tag doesn't match its opening tag — check line 1.

Questions

Asked often, answered plainly.

( 02 )
Does the validator check my DTD or XSD schema?

No — it checks well-formedness: the syntax rules every XML document must follow, enforced by the browser's native parser. That covers unclosed tags, mismatched tag names, unquoted attributes, bare ampersands, duplicate attributes, multiple root elements and premature endings — which is where the vast majority of real-world XML breaks. Validation against a DTD or XSD schema requires server-side tooling and is out of scope for a page with no backend.

What's the difference between the Formatter and the Beautifier?

Same engine, more knobs. The Formatter is the one-button standard: parse and re-emit with your chosen indentation, attribute order preserved exactly as written. The Beautifier adds alphabetical attribute sorting on every tag, applied recursively through the whole tree, which makes output deterministic and diffs meaningful.

Will minifying change my data?

No. Only whitespace-only text between tags is removed — that whitespace is layout, not content. Meaningful text, CDATA sections, comments, attributes and processing instructions survive byte-for-byte, and re-parsing the minified output yields the same tree as parsing the original. What changes is the byte count, nothing else.

Why does a bare & break my XML?

Because & starts an entity reference in XML, so the parser immediately tries to read one and fails when no valid entity follows. Escape it as &amp; — and < inside text as &lt;. If a whole block of text is full of special characters, wrap it in a CDATA section instead; the formatter, beautifier and minifier all preserve CDATA untouched.

Is my XML saved anywhere?

No. IrisTool has no backend and no database. Parsing happens inside your browser tab and the data disappears the moment you close or refresh the page. There is nothing to leak, because nothing is ever collected.
