          01 / 03
          
CSV ↔ JSON

          runs in the bench above
        

        

          
Turns a header-row CSV into an array of JSON objects — one object per row, keyed by the header — and back again. This is a real CSV parser, not a naive split: quoted fields survive embedded commas and newlines, doubled quotes ("") become a literal quote, and on the way back any field containing a comma, quote or newline is re-quoted automatically. The 123 auto-type toggle converts values that look like numbers and booleans into their JSON types; switch it off to keep everything as strings for exact round-tripping.

          

            Example · CSV → JSON
            
name,missions,active
"Armstrong, Neil",3,true

            ↓
            
[ { "name": "Armstrong, Neil", "missions": 3, "active": true } ]
the quoted comma stays inside the field.

          

          
Use it for spreadsheets → APIsdata importsexportsETL quick-turns

        

      


      
      

        

          02 / 03
          
YAML ↔ JSON

          runs in the bench above
        

        

          
Speaks the config-file YAML you actually meet: key–value maps, nesting by indentation, arrays of scalars or objects, inline [a, b] and {a: 1} collections, quoted strings, numbers, booleans and null. To JSON it goes as a native object; from JSON it's re-serialized as clean indentation-based YAML with arrays as - items. It's a practical subset — anchors, multi-line scalars and tags are out — but it covers the everyday cases with no server round-trip.

          

            Example · YAML → JSON
            
crew:
  - name: Neil
    role: Commander
manned: true

            ↓
            
{ "crew": [ { "name": "Neil", "role": "Commander" } ], "manned": true }
indentation becomes structure.

          

          
Use it for config filesCI/CD pipelinesk8s manifestssettings ↔ API

        

      


      
      

        

          03 / 03
          
XML ↔ JSON

          runs in the bench above
        

        

          
Bridges the markup world and the object world with a clear, reversible mapping: attributes become @name keys, text content becomes #text (or the whole value for a leaf element), repeated siblings become arrays, and element text that looks like a number or boolean gets typed. The reverse conversion reads @ back into attributes and #text back into content, emits a proper XML declaration, and escapes everything that needs it — so the structure survives the round-trip.

          

            Example · XML → JSON
            
<mission year="1969">
  <member role="Commander">Neil</member>
  <member role="Pilot">Buzz</member>
</mission>

            ↓
            
{ "mission": { "@year": "1969", "member": [ { "@role": "Commander", "#text": "Neil" }, … ] } }
attributes, repetition and text all accounted for.

          

          
Use it for legacy APIsSOAP responsesfeedsconfig bridges

Questions
Asked often, answered plainly.

        ( 02 )
      


      

        How does the CSV converter handle commas inside fields?
        
It speaks real CSV, not naive split-on-comma. Quoted fields are parsed correctly, doubled quotes ("") become a literal quote, and commas and newlines inside quotes are preserved as part of the field. On the way back to CSV, any field containing a comma, quote or newline is automatically re-quoted, so nothing leaks out of its column.

      

      

        Does the CSV converter turn numbers and booleans into JSON types?
        
By default, yes — the 123 auto-type toggle converts values that look like integers, decimals, true or false into their proper JSON types, which is usually what you want for an API. Turn it off if you need every value preserved as a string, which is the safer choice when exact round-tripping matters more than typed output.

      

      

        What YAML does the converter understand?
        
The everyday subset: key-value maps, nesting by indentation, arrays with - items (including arrays of objects), inline [a, b] and {a: 1} collections, quoted strings, numbers, booleans and null. It doesn't cover the full YAML spec — anchors, multi-line scalars and custom tags aren't supported — but it handles the config-file YAML you meet in the wild.

      

      

        How does XML map to JSON?
        
Attributes become @name keys, text content becomes #text (or the whole value for a leaf element with no attributes), repeated sibling elements become arrays, and element text that looks like a number or boolean is typed. The reverse conversion reads @ back into attributes and #text back into content, so a round-trip preserves the structure.

      

      

        Is my data saved anywhere?
        
No. Stack has no backend and no database. Every parse and serialization happens inside your browser tab and vanishes the moment you close or refresh the page. Nothing is logged, because nothing is ever collected.
