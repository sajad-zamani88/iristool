UUID Generator

runs in the bench above

The standard issue: a version 4, variant 1 UUID per RFC 4122 — 128 bits where 122 are pure cryptographic randomness and six are fixed markers that identify the version and variant. The spotlight lights up both marker bits so you can see exactly where they live (the 4 and the leading 8/9/a/b of the fourth group). Format it your way — upper or lower case, hyphens on or off, braces on or off — and pull a batch of up to 25 at a time.

GUID Generator

runs in the bench above

Same 128-bit engine, different dress code. A GUID is Microsoft's name for a UUID, and by convention it's written uppercase and wrapped in braces — the form you'll see in .NET, the Windows registry, COM interfaces and Active Directory. This tool generates the identical v4 random value and simply presents it the way those systems expect, ready to paste into a C# literal or a .reg file.

Nano ID Generator

runs in the bench above

The compact contender. A Nano ID draws from a 64-character URL-safe alphabet (A–Z, a–z, 0–9, _ and -), so every character carries 6 bits of entropy — a default 21-character ID packs about 126 bits, slightly more than a UUID, in far fewer glyphs. Drag the length dial from 6 to 64 and watch the entropy readout tell you exactly how much randomness you still have. Safe in URLs, filenames and keys with no escaping needed.

Questions

Asked often, answered plainly.

( 02 )
What's the difference between a UUID and a GUID?

Underneath, nothing — both are 128-bit values drawn from the same random space. The difference is convention: UUID is the RFC 4122 standard, usually written lowercase with hyphens; GUID is Microsoft's name for the same thing, conventionally written uppercase and wrapped in braces. This bench generates the identical v4 random value and simply dresses it differently for each tool.

Are these actually random?

They come from your browser's cryptographic random number generator (crypto.getRandomValues), which is seeded from hardware entropy and is the same source your operating system uses for TLS keys. A UUID v4 carries 122 bits of true randomness and a default Nano ID about 126. That's not "pseudo-random enough" — it's cryptographically secure for identifiers, tokens and keys.

Can two generated IDs collide?

In practice, no. The v4 space holds 2^122 values; by the birthday bound you'd need to generate roughly 2^61 — about two quintillion — identifiers before a collision became even 50% likely, and Nano IDs are in the same league. For any realistic system, from a side project to a planet-scale database, treating them as unique is safe.

Why is a Nano ID shorter than a UUID?

Because it uses a larger alphabet. A UUID speaks in hex — 16 symbols, 4 bits per character. A Nano ID speaks in 64 URL-safe symbols — 6 bits per character — so 21 characters carry about 126 bits, slightly more than a UUID's 122, in far fewer glyphs. Shorten it and the entropy readout on the bench tells you exactly what you still have.

Is my data saved anywhere?

No. Stack has no backend and no database. The identifiers are generated inside your browser tab and vanish the moment you close or refresh the page. Nothing is logged, because nothing is ever collected.
